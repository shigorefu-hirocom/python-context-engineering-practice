# 第15回 自主課題：プロジェクトの情報を整える

三つの小さなPythonプロジェクトを扱います。プログラムの実装と実行結果を確かめ、次に作業する人やエージェントに必要な情報を文書に残します。

| 課題 | 公開リポジトリ | 提出するもの |
| --- | --- | --- |
| 1. 初めて見るプログラムのREADME | [1](https://github.com/shigorefu-hirocom/1) | 自分で作成したREADME.md |
| 2. 古いドキュメントの更新 | [2](https://github.com/shigorefu-hirocom/2) | 更新したREADME.mdとdocs、変更を記録したコミット |
| 3. エージェントの作業範囲 | [3](https://github.com/shigorefu-hirocom/3) | 更新したAGENTS.mdと、出力した100件のJSON |

課題ごとに対象のフォルダーを作業ディレクトリにしてください。文書とコメントは日本語で書きます。AIにコードの読み方やエラーの調べ方を相談できます。説明が正しいかは、自分でコードや実行結果に照らして確かめてください。

## 配布物の取得

取り組む課題のリポジトリを上の表から開き、個別にクローンできます。課題の条件は各リポジトリのTASK.mdにあります。三つをまとめて取得する場合は、次のコマンドを実行します。

```bash
git clone --recurse-submodules https://github.com/shigorefu-hirocom/python-context-engineering-practice.git
cd python-context-engineering-practice
```

すでに全体をクローンした場合は、クローンしたフォルダーで `git submodule update --init` を実行すると各課題のサブモジュールを取得できます。

課題2の文書をコミットする前に、課題2のフォルダーで `git switch -c documentation-update` を実行し、自分の作業ブランチを作ってください。課題2だけを取得する場合は、[備品貸出のリポジトリ](https://github.com/shigorefu-hirocom/2)をクローンしてください。

## 課題1 初めて見るプログラムのREADME

支出データを扱うプログラムを引き継ぎます。Pythonファイル、CSV、依存パッケージを記したファイルが用意されています。初めてこのフォルダーを受け取った人が使い始められるよう、READMEを作ってください。

1. Pythonファイルを読み、プログラムの目的、使っているライブラリ、実行の入口、CSVを読み込む処理を調べます。
2. 自分の環境で起動できるように準備します。インストールするパッケージと、Tkinterを利用できるか確認する方法を調べます。
3. 起動して、どのデータが表示されるか、画面の操作で何が変わるか、グラフに何が表示されるかを確かめます。
4. `01_expense_viewer/README.md` を新しく作ります。以下の内容を、初めて使う人が順番に確認できるように書いてください。

| READMEに書くこと | 確認する内容 |
| --- | --- |
| プログラムの概要 | 何のデータを扱い、何ができるか |
| 実行環境と準備 | Python、依存パッケージ、Tkinterの確認方法 |
| 実行方法 | 作業ディレクトリと起動コマンド |
| 画面の使い方 | データの表示、操作手順、グラフの見方 |
| 入力と出力の例 | CSVの列と、実際に確認した表示・集計結果 |

最後に、自分が書いた手順を最初からたどって起動し、記載した操作を確認してください。提出するのはREADME.mdです。

## 課題2 古いドキュメントの更新

備品の貸出を管理するプログラムには、アプリケーションの変更を記録した10件のコミットがあります。その後に、配布条件を記したTASK.mdを追加したコミットがあります。機能が追加されたあとも、READMEとdocsには最初の版の説明が残っています。現在のコードと利用方法を調べ、次の利用者が正しい手順で使えるように文書を更新します。

1. `02_equipment_rental/` を開き、`git log --oneline` で履歴を確認します。READMEとdocsを読み、実行手順、機能、データの場所に関する記述を探します。
2. `git show` などで変更の差分を読み、現在のコードと照らし合わせます。説明と実装が異なる箇所を整理します。
3. 現在のプログラムで備品の貸出と返却を確認します。貸出後に終了してもう一度起動し、状態がどうなるかを確かめます。配布されたテストの実行方法も調べて実行します。
4. `README.md` と `docs/` の説明を更新します。READMEには最初に必要な準備と実行手順をまとめます。詳しい操作、データの扱い、確認方法は関連するページに書きます。READMEから詳細ページに移動できるよう、相対リンクも確認してください。
5. `git diff` で変更内容を見直し、文書の修正をコミットします。コミットの説明には、主な修正内容と、どの実行結果や差分を根拠にしたかを書いてください。

提出するのは更新したREADME.md、docs、および変更を記録したコミットです。履歴を含む配布フォルダーで作業し、Pythonファイル、配布データ、テストは確認に使います。

## 課題3 エージェントの作業範囲

SQLiteの学習用データベースに100人分の架空の生徒データが入っています。配布されたPythonプログラムは、データベースを読み込み、一人ずつJSONファイルに出力します。配布時のAGENTS.mdには、作業に必要な範囲を超える指示が書かれています。

1. `03_student_export/AGENTS.md` をエディターで普通のテキストとして開きます。Pythonコードと比較し、読み取るデータ、作成するファイル、必要な作業範囲を調べます。
2. AGENTS.mdを書き直します。どのファイルを読めるか、どこに何を作成できるか、入力が見つからない場合や同名の出力がある場合にどうするかを明確にしてください。エージェントを利用する場合は、この見直しを終えてから対象のフォルダーを開きます。
3. `03_student_export/` を作業ディレクトリにして `python main.py` を実行します。`output/` に100件のJSONが作成されたことを確認し、いくつか開いて生徒番号、名前、クラスが一人分ずつ書かれているかを確かめます。
4. もう一度実行して、同名ファイルの扱いと作成件数を確認します。観察した動作と、AGENTS.mdに書いた指示が一致するか見直してください。

提出するのは、更新したAGENTS.mdと `output/` の100件のJSONです。SQLiteの操作は配布コードに含まれています。取り出した行を繰り返し処理し、辞書をJSONとして保存する箇所を確認してください。
